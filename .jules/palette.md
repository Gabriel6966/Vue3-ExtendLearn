## 2023-10-27 - Spanish localization and dynamic encoding in component views
**Learning:** When using search-and-replace tools on files with localized characters (like "Añadir"), the trace might display them as escaped Unicode (`A\303\261adir`). The `REPLACE` block should use proper Unicode (`A\u00f1adir`) to avoid rendering literal backslashes in the UI, and post-processing with `sed` may be required to ensure the unescaped characters are saved correctly in the source file. Also, `var(--color-text)` does not exist; empty state messages require plain wrapper elements (e.g. `<div>`) to inherit the global `#2c3e50` correctly instead of using `<p>` tags.
**Action:** When modifying Spanish UI components, strictly verify the character encoding in the final file output using `sed` or `cat`, and avoid adding custom CSS styles to empty states; rely instead on plain structural tags.
